# 花舞之街 · 网站源码

结构与设计取舍见 `ARCHITECTURE.md`，常见改动的做法见 `EXTENDING.md`。

`_src/` 为源码，仓库根目录为 `build.mjs` 压缩后的发布版。GitHub Pages 不发布以下划线开头的目录。

## 文件

| 文件 | 内容 |
| --- | --- |
| `config.js` | 站点内容：最新活动、往期活动、小型回顾、相册、日历标注、图片地址 |

| `admin.js` | 内部入口与管理页，进入 `#internal` 时加载 |
| `huayu.js`、`huayu/` | 花语，打开时加载 |
| `puzzle.js` | 花街拼图（「更多」里的百宝箱），打开时加载 |
| `bard.js` | 吟游诗人模拟器（「更多」里的竖琴），打开时加载 |

脚本顺序：boot → verify → config → main → ticket → venue → survey；admin、huayu、puzzle、bard（及 bard-stage）、games（及 games-poems）、`assets/lib/exceljs.min.js` 按需加载。
字体自托管于 `assets/fonts/`，标题字为 `assets/site/brush.woff2`（现有标题用字，开屏预加载）与 `brush-ext-*.woff2`（常用字切片，用到才下载）；艾欧泽亚文字字体在 `assets/fonts/eorzean/`，用 class `eorzean`（Augmented Neo-Eorzean）、`eorzean-classic`（Eorzea）、`hingashi`（Hingashi Extended）调用，未使用时不会下载。

后端为 Cloudflare Worker（不在本仓库），挂在本站 `/api/*`，数据在 D1，图片在 R2。

## 花语

- 一代：「听花语：」+ 草木字；二代：散文句式。写入用管理页选定的版本，读取时自动识别。
- 加解密在 Worker，密钥只存在 D1，网站不保存明文与花语。
- `zi.js`、`zi-data.json`、`v1.js`、`v2-*.js` 决定花语格式，改动会导致旧花语无法解读。需要新格式时新增一代并在 `huayu.js` 的 `ALGOS` 登记。
- 自测：`node huayu/selftest.mjs`

## 花街拼图

- 原图取 `config.js` 的 `INFO_GALLERY`；难度与限时在 `puzzle.js` 开头的 `DIFFS`：鱼信 36 块 / 鱼丽 60 块 / 光风院霁月 128 块（块数固定，按图片宽高比挑行列），限时 7 / 15 / 35 分钟。改块数要同时改 Worker 的 `PUZZLE_PIECES`。
- 中断继续：管理页「花街拼图」开关，默认关闭。开启时进度存在访客本机 `hj_puzzle_save`；关闭时关掉拼图即放弃本局（× 要点两次）。
- 限时模式鱼丽及以上通关时，调用 `huayu_seal`（`v: 1, purpose: "puzzle", key: "huajiepintu"`）用一代花语生成通关码，去掉「听花语：」前缀。密钥为自定义密钥 `huajiepintu`（`puzzle.js` 的 `CODE_KEY`，Worker 的 `PUZZLE_CODE_KEY` 与它一致：`purpose` 为 `"puzzle"` 时固定用它加密，不看前端传来的 key），管理页「花语加密」或访客花语工具粘贴通关码并填上密钥即可解读。
- 大赛拼图：管理页设置名称、时段、难度、图片（裁剪后走公告配图上传，存 R2）。时段内拼图首页出现入口，正计时；开局时 Worker 发开局凭证，通关后访客填写游戏 ID，`puzzle_contest_submit` 按服务器时间核对耗时并记入 `puzzle_records`，再生成一代通关码。更换图片或难度算新一届（`contest_rev`）。
- 网格提示：拼图区画虚线拼块格子，打开时拼块放到正确格子附近会吸附过去。大赛里「显示原图 / 仅显示边框图块 / 网格提示」是否可用由管理页勾选（`puzzle_contest_tools` 按位存，默认全开）。
- 原图 / 仅显示边框图块 / 网格提示每局默认关闭；本局用过哪些写进通关码（「辅助功能」一行）和大赛记录（`aids`）。
- 大赛暂停计时（管理页「暂停 / 切到后台时」，`puzzle_contest_pause`）：停止计时（默认，暂停、切后台不计）/ 继续计时（耗时 = 现在 − 开局凭证里的服务器开局时刻，暂停、切后台、关掉再继续都照算）。
- 大赛参加次数（管理页「每个浏览器最多参加几次」，`puzzle_contest_max`，0 为不限）：每点一次「参加大赛」拿到开局凭证算一次，继续中断的那局不算；按届记在访客本机 `hj_puzzle_entries`，次数用完按钮变灰。只是前端限制，换浏览器或清网站数据会重新计。
- 本机记录 `hj_puzzle_records`：最近 30 次通关和各难度（大赛按届）的最短用时，拼图首页「我的记录」可查看、清空。成绩按「计入用时」比较：耗时 + 辅助加时，仅显示边框图块 +10%（至少 1 分钟）、网格提示 +25%（至少 2 分钟），两项都用时依次相乘（`puzzle.js` 的 `AID_PENALTY`，管理页 `admin.js` 的 `PZ_AID_PENALTY` 要一起改）；显示原图不加时。通关卡片、通关码（有加时才多一行「计入用时」）、管理页参赛记录（「计入」列，按耗时排序时按它排名次）都用这个规则。
- Worker 接口：`puzzle_state`、`puzzle_contest_start`、`puzzle_contest_submit`、`puzzle_admin_get` / `_set` / `_records` / `_void`；`get_site_state` 带 `puzzle`。

## 吟游诗人模拟器

- 玩法参考 [blossom](https://github.com/alexbainter/blossom)（MIT）：开始演奏后点页面任意位置，高度决定音高（默认 C 大调五声音阶），左右决定声像。每个音隔 7~12 秒回响一次、逐渐变弱，最多循环最近 15 个音。再点按钮或按 Esc 结束。
- 乐器表在 `bard.js` 开头的 `INSTRUMENTS`：弦乐 8 种、管乐 10 种，默认钢琴。`low` 为最低音的 MIDI 编号，`oct` 为八度数：钢琴、竖琴用 blossom 的宽音域（C2–C7），鲁特琴 C2–C6，其余三个八度、参考游戏内乐器演奏。`gain` 已按实测响度校准，新增或改动音色后要重新比对音量。
- 钢琴用 blossom 同款真实采样（VSCO 2 社区版，CC0），在 `assets/bard/piano-<MIDI 编号>.mp3`（C♯2–C♯7，每隔大三度一个，保留 8~12 秒混响尾巴和原有的音区响度），播放时取最近的变调；打开小组件且选着钢琴时才下载（约 830 KB，等小组件弹出来、浏览器空闲时再开始），没下载好时用合成钢琴。采样自带混响，钢琴不再送进站内混响。其余音色用 Web Audio 合成，不下载文件。
- 音频会话（`bard.js` 的 `holdPlayback`）：iPhone 上网页音频默认跟着侧边静音键走。开始演奏、打开舞台时，支持 `navigator.audioSession` 的设为 `playback`；不支持的 iOS（较旧系统、部分 App 内置浏览器）在点按里循环播放无声的 `assets/bard/silence.wav`，把会话切到「播放」类别；结束 / 离开舞台时恢复。安卓不放（会多出媒体通知）。`AudioContext` 不在 running（含 iOS 的 interrupted）就 resume。叫醒时顺带放一个 1 采样的静音音源（`kick`，部分安卓内置浏览器 / WebView 只 resume 不出声）；舞台在 pointerup / touchend / click 上音频没在运行时再叫一次（安卓只把手指抬起算作用户操作）。
- 打开小组件要轻：手机上（`pointer: coarse` 或宽度 ≤ 760）只淡入、毛玻璃模糊半径减小（毛玻璃上做缩放每帧都要重新模糊），并加 `contain: layout style`；动画关闭（`body.fx-off`）时不弹出、不晃动；「更多」里按下竖琴就开始下载 `bard.js`，选了功能后菜单直接收起（`.more-panel.is-instant`），不和小组件同时做动画；手机上不把焦点移到「开始演奏」。
- 输出末级有限幅（`ensureAudio` 里的 limiter），音叠得再多也不会削波出「滋滋」声；改音量相关参数后用离线渲染确认峰值仍低于 0 dBFS。
- 「高级功能」按钮在「开始演奏」左边，点开向上展开（不记忆展开状态），里面的设置都存本机 `hj_bard_opts`：
  - 音阶：C 大调 / D 大调（`KEYS`，D 大调整体升一个全音，辅助线五线谱带调号、唱名按首调 1=D）；音域：五声 / 七声（`SCALES`），选项上的音数随乐器变（三个八度的乐器 16 / 22 个音，钢琴、竖琴 26 / 36 个）。七声加了 fa、si，回响叠在一起时偶尔不和谐。演奏中改了，已在回响的音保持弹下时的音高。
  - 三个勾选项：辅助线（默认关，鼠标附近显示上下几档音高的横线与音名，旁边一张小五线谱标出当前音和相邻两音，超出谱表时记 8va / 8vb）、回响循环（默认开，关掉立即取消排队中的复读）、音色位置（默认开，关掉后左右不影响声像）。下拉框第一项为钢琴。
- 回响中的音保留自己的音色，演奏中换音色可以叠出合奏。演奏时背景音乐暂停，结束后恢复；站内静音时不能开始。
- 「更多」里的入口图标取自游戏原版职业图标的字形（`assets/site/bard-glyph.png`，只留形状作遮罩，颜色跟随其他按钮），不要改画。
- 只用到本机：选的音色存 `hj_bard_inst`，小组件位置存 `hj_bard_xy`（拖标题栏移动，双击复位）。

## 舞台演奏（音游）

- 入口：吟游诗人模拟器「高级功能」里的「熟练了？上舞台演奏！」，按需加载 `bard-stage.js`，全屏一层（`#hjStage`），自带固定配色，不跟白天 / 夜晚模式变。按钮、选项、卡片用和网站其他页面同一套「凸起玻璃」（`.hjs` 里固定为夜间那套 `--glass-*` 变量，选中用紫藤色、开始 / 主按钮用金色；演奏中的分数、连击和 3·2·1 倒数保持无边框），标题用标题毛笔字；左上角图标为 `assets/bard/stage/stage-icon.webp`（游戏道具图标抠图）。发声借用 `bard.js` 的音源：`HJBard.playMidi(音高, 力度, 乐器, 声像, 推后秒数)`、`unlock`、`prepare`、`clock`（AudioContext 的 `currentTime` 与输出延迟）。
- 曲子全部来自 MIDI（吟游诗人演奏用的 MIDI，大多是单轨），没有另配的伴奏 / 示范音轨：谱面挑出来的音是气泡，由玩家弹；其余的音（和声、这一档省掉的旋律）由游戏按时间用轻音补上，整首始终完整。整首都用设置里选的音色（默认「跟随曲目」用 MIDI 原本的乐器，也可跟随模拟器或指定一种）。
- 三档难度：仙人刺 / 魔界花 / 泰坦（`DIFFS` 的 `label`；`id` 与本机纪录的键仍是 easy / normal / hard，改名不影响旧纪录）。玩法说明（`renderHelp`）里判定模式、点击范围与得分扣减合在一条里讲。
- 玩法：气泡出现在音高对应的高度上（越高音越高），外圈收缩到与核心重合时弹它就发出这个音。判定 Perfect / Great / Good / Miss，设置里三种判定模式（`hj_stage_judge`）：正常（默认，半窗按难度收紧：仙人刺 0.18 / 0.30 / 0.45、魔界花 0.14 / 0.24 / 0.36、泰坦 0.11 / 0.19 / 0.29 秒，在 `DIFFS` 的 `win`）、宽松（三档都用 `LOOSE_WIN` 0.18 / 0.30 / 0.45）、放水（判定窗同宽松，不用点：指针停在气泡上〔离中心 `HOVER_R` 个气泡直径内，手机上手指按住滑过去〕，到点自动算弹中，来晚了还在判定窗内就按晚了多少算；点也照样算）；点气泡的判定范围在设置 → 操作 →「点击范围」（`hj_stage_range`，`TAP_RANGES`）：正常（默认）判定半径为气泡直径的 1.4 倍，下一个该弹的气泡附近没别的可算时放宽到 1.7 倍；宽松为 1.7 / 2.2 倍；放水不看位置，判定窗里最早那个，点屏幕任意位置或按任意键都算）。点击范围和判定模式都选放水 = 自动演奏（`isAuto`）：每个音到点自动弹中，玩家点了不算，不计分、不记纪录，结算像学习模式一样只显示弹了几个、写明「自动演奏」，弹中提示「AUTO」。一次点按先算给判定窗里最早还没弹的音（`pickNote`），只有明显点在后面那个气泡正中、或最早那个已晚过 GREAT 窗时才跳过它，免得气泡挨得近时一下错位、后面每一下都跟着错，点按排队的时间用事件的 `e.timeStamp` 补回最多 50 ms（有的手机浏览器时间戳时基不对，认出来就整局不用），判 MISS 前再多等一会儿（`missGrace`：至少 0.1 秒，JUST 更宽时等到 JUST 结束）。JUST（`JUST_RATIO`）：一下按正常规则都没算到（本来要算点空）时，再看比 GOOD 早或晚出去不到 GOOD 半窗三分之一（泰坦正常判定约 0.1 秒、魔界花 0.12、仙人刺 / 宽松 0.15）、在点击范围里的那个音，算 JUST —— 出声、按权重 0.5 计判定分，但断连击；准确率里按半个 GOOD 算。只在本来要点空时才看，不会抢走判定窗里的音，防多米诺的规则不受影响。暂停窗口显示到目前为止的成绩：进度、分数、准确率、连击、最大连击、点空、各档计数（学习 / 自动演奏只显示弹了几个）。非 PERFECT 时判定字下面标「早 / 晚 xx ms」；判定字正下方常驻连击数（0 时变暗，倒数等提示出现时让开）。结算显示平均早晚、点空次数及原因（`ghostWhy`：偏早 —— 点处附近的气泡还没到判定窗；偏晚；点偏 —— 判定窗里有没弹的气泡但不在点击范围内），和一行设备诊断（输出延迟、点按排队、掉帧比例：按本机刷新率算，开头 120 帧的中位数当一帧的长度，长过一半就算掉了一帧，单独掉一帧也算；并标出掉帧最多的 4 秒在哪、最长一帧多久）；结算各档计数为 PERFECT / GREAT / GOOD / JUST / MISS；结算单独列出难度、判定模式、点击范围（学习 / 自动演奏另列「模式」）；得分规则见下面「得分与评级」；演出模式一个 MISS 都没有时显示「FULL COMBO!」。学习模式弹中提示「WELL」。暂停窗口：继续 / 重来 / 停止演奏；结算：再来一次 / 下一首 / 结束演奏；演奏中右上角 ✕ 为「结束演奏」。舞台淡入盖满后给 body 加 `hjs-covered`：下面的网站（`style.css` 里点名的页头、正文、页脚、背景特效、弹窗、模拟器小组件）`visibility: hidden` 并暂停 CSS 动画，不参与绘制；浮在舞台上的下拉选单、加载提示等不受影响，新加挂在 body 上、会被舞台盖住的大块内容时记得补进名单；演奏时背景压暗用遮罩底色，不用 filter。连续掉帧超过两成自动切省电画法（`.hjs.is-lite`，去掉气泡光晕）。设置 → 画面可选「正常显示」（默认）/「简单显示」（`hj_stage_render`，`.hjs.is-simple`：去掉气泡光晕、音名 / 判定字 / 连击 / 分数的模糊阴影和提示条毛玻璃，音名描边保留）。没有血量；漏掉的音不出声；声像固定居中。
- 得分与评级（`bard-stage.js` 的 `SCORE`、`CAPS`、`RANKS`）：满分 1,000,000，与曲子长短无关，= 判定分 700,000 + 连击分 300,000（N 为这一档要弹的音数）。
  - 判定分：每个音的基础分 500000 / N × 权重（PERFECT 3、GREAT 2、GOOD 1、JUST 0.5、MISS 0），累加成原始分（全 PERFECT 150 万），按 `SCORE.curve` 折算：原始分 0~50 万按 70%、50 万~100 万按 42%、100 万~150 万按 28%，全 PERFECT 正好 700,000（35 万 + 21 万 + 14 万）。
  - 连击分：最大连击 / N 分档（`SCORE.combo`），从 5% 到 95% 每 5% 一档，全连 30 万，5% 及以下 0。原有的点：超过 30% 15 万、40% 18 万、50% 21 万、60% 22 万、70% 23 万、80% 24 万、85% 25.5 万、90% 27 万、95% 28.5 万；其余各档（5% 3.1 万、10% 6 万、15% 8.6 万、20% 11 万、25% 13.1 万、35% 16.6 万、45% 19.7 万、55% 21.6 万、65% 22.5 万、75% 23.4 万）按原有的点用保形单调插值（PCHIP，过原点）补齐、取整到千位。玩法说明不列这些细档。
  - 上限（`capOf`）：判定模式与点击范围的组合 —— 都正常 100 万、一项宽松 80 万、两项宽松 70 万、一项放水 65 万、宽松 + 放水 60 万（两项放水 = 自动演奏，不计分）。上限的九成以内照算，往上把剩下的分按比例压进最后一成（`capScore`），每个音都还有分，打满正好等于上限。大厅、设置、结算都写明「得分上限 xx 万（…）」。
  - 演奏中分数按已弹的音实时算（判定分 + 按当前最大连击的连击分，再套上限），只涨不跌；暂停卡、结算写明「判定分 + 连击分」。
  - 评级按得分（`RANKS`，结算时算）：D（1 起）、D+ 40 万、C 50 万、C+ 60 万、B 70 万、B+ 80 万、A 85 万、A+ 90 万、almost S 92.5 万、S 95 万、SS 98 万、SSS 99 万、SSS+ 99.5 万、Impeccable 100 万；0 分、学习模式、自动演奏为 Complete。本机纪录的评级按存的得分重新算，旧纪录里的「完美」「完成」显示为新名字。
  - 本机纪录 `hj_stage_best3`（键 `曲目:难度:判定模式:点击范围`）记最高分与评级（另记准确率、最大连击）。百万分制以前的 `hj_stage_best2` 保留不删：读的时候按它记的准确率和最大连击用新公式换算（准确率只记到 0.1%，有几百分误差），与新纪录比取高的；旧键 `曲目:难度:判定模式` 当正常范围、`曲目:难度` 当宽松判定 + 宽松范围读。
- 飞花线（设置 → 画面，`hj_stage_fly`，默认开；访客自己关过的保持关）：萤火虫大小的花（`assets/bard/stage/fly-flower.webp`，取自设计稿，约 1/4 个气泡，带一圈静态的径向渐变光晕）沿一条平滑曲线掠过每个气泡。路径开演前算好：各气泡（同一刻的和弦只取第一个）按时间连成 Catmull-Rom 曲线，布局时把每段的三次式系数算完（`flyLayout`），演奏时每帧二分找段、代入时间；花在气泡该判定的那一刻正好经过它（`FLY.ahead`：提前多少秒经过，现在 0），两个气泡之间按时间匀速走。正常显示身后撒星星（`fly-stars.webp` 白 / 黄 / 桃三种，固定 `FLY.stars` 个元素轮流用，每颗约 1 秒）；简单显示拖一条细金线（一条 SVG 路径：取花在过去 `FLY.tail` 秒里走过的 `FLY.samples` 个点，用中点二次曲线连成平滑的线，渐变从花这头往尾巴渐隐，没有外圈光带）。花、星星都是固定元素、各自常驻一层，每帧由 JS 写 transform / opacity（花的转角也写在同一个 transform 里），不跑 CSS 动画、不用 Web Animations（那样浏览器会把上面的元素都拆成单独的层，正常显示曾因此掉帧九成），也不用整屏 canvas（有的手机上整屏重画很慢，会拖慢点按处理，出现点了不判定）；花停着、星星散完、线收拢时什么都不改；整层在气泡下面（z-index 1），不挡音名；系统开了「减少动态效果」时花不转、不撒星星。
- 气泡每帧只改外圈、核心两层的 transform / opacity（`setK`，变化不到 0.002 不写），不用 CSS 变量（改变量会让整个气泡连同音名重算样式、重画文字）；音名也常驻一层，每帧只改透明度（收缩过半后渐亮，到点最亮），不重画文字。外圈、核心、音名都是常驻的单独一层，不会一会儿建层一会儿拆层。
- 暂停后继续：和开头一样的预备拍（按曲子的拍子响四下「嗒」，后三下显示 3·2·1，再过一拍接着走），倒数时钟不走、点了不算，倒数中再按暂停 / 切后台就回到暂停。
- 开演前的准备（`warmSounds`，超过 0.35 秒就出转圈的莫古力）：谱面、音色与音高预先算好、开了飞花线时花和星星两张图下载并解码好（解码最多等 2.5 秒：页面在后台时浏览器不解码，不能卡住），都在预备拍之前做完。
- 掉帧诊断的「一帧多长」：开头 120 帧的第 15 百分位，再贴到最近的常见刷新率（60 / 75 / 90 / 120 / 144 / 165 Hz），开头就卡也不会把刷新率估低。
- 时钟：模拟器 AudioContext 的 `currentTime`，补音也排在同一个钟上（另用 25 ms 计时器提前 0.12 秒排，画面掉帧也不漏音）；画面与判定 = 音频位置 − 输出延迟 − 判定延迟。暂停、切后台、学习模式都是停这个钟。音频叫不醒时提示「点击屏幕开始」。
- 操作：只有点气泡（键盘轨道模式反直觉，已去掉；访客本机旧的 `hj_stage_input` / `hj_stage_lanes` / `hj_stage_codes` 打开舞台时删掉）。气泡沿旋律左右铺开；电脑上鼠标指着气泡按键盘任意键（F1~F12、Tab 和 Ctrl / Alt 组合键除外）或鼠标左右键都算在鼠标处点一下（放水判定不用按）；放水点击范围下没动过鼠标、直接按键也算。
- 气泡摆放（`bard-stage.js` 的 `placeNotes`）：同时在屏幕上的气泡尽量不重叠，每个音在一组候选位置里挑代价最小的；待在视线里：下一个出现在上一个旁边（1.3~2.3 个气泡远，间隔越久越远），整体往屏幕中间收，太密时才去远处找空位；高度跟旋律走向（每半音约 0.18 个气泡）而不是按绝对音高铺满整屏；尽量顺着一个方向走、不急转回头；挨得近的两个气泡一定不同色（默认按音高四色，撞色时换色，多备两色）；先到的气泡叠在上面；下一个该弹的气泡离判定点不到 0.3 秒时外圈加粗（太早加粗会让人一亮就点、早一拍）；气泡里的音名加粗加描边，到点时最亮。玩法说明里写明 MISS（到点没弹，音不响、断连击、算准确率）和「点空」（点了但附近没有该弹的气泡，不扣分不断连击，只记次数）的区别。
- 开演前备音色：`HJBard.warm(乐器, 音高列表)` 把这首用到的每个音高（要弹的、补音、预备拍）先算好再开钟。拨弦与合成钢琴的音是第一次弹到时才在主线程上算（每个几毫秒到几十毫秒），不先算的话演奏中碰到新音高会掉帧；分 8 ms 小块算，缓存上限放宽到装得下这一首。钢琴等采样乐器等采样下载完（最多 10 秒）。超过 0.35 秒没好就出全屏转圈的莫古力（`trackLoad`）。
- 「示范旋律」：要弹的音也先轻轻放一遍。曲子第一个音前有四下预备拍并显示 3·2·1。
- 学习模式：不计分，气泡到判定点还没弹就把钟停在这一拍（补音只排到这一拍之前），弹中才继续。
- 界面分层：大厅（今晚演奏、难度、模式、开始）/ 选曲窗口（搜索、分类与星级筛选、点一下用 MIDI 试听 8 秒）/ 设置窗口（声音：音量即全站音量、音色、示范旋律；操作：点击范围；画面：显示、飞花线；时机：判定模式、判定延迟与校准）/ 玩法说明。Esc 与手机返回键都是「回到上一层」（打开时 `history.pushState`）。
- 延迟校准：在同一个音频钟上排 10 下「嗒」，跟着按键或点圆圈，取后几下偏差的中位数（拍点在 `bard-stage.js` 的 `CAL`）。
- 曲库在 `assets/bard/stage/`：`songs.json`（公开曲目的索引：曲名、分类、三档星级、时长、速度、音域、三档音数）、`songs-all.json`（全部曲目的索引，网页代码里不写它的地址）、`charts/<id>.json`（每首的音符与分级，点到这首才下载）、`bg.jpg` 舞台背景。
- 隐藏曲目与曲库密码：`songs.py` 里写了 `show=True` 的曲子公开（现在是卡农、致爱丽丝、月光、夜曲 Op.9 No.2 四首公版古典），其余隐藏。选曲窗口的搜索框输入曲库密码按回车，`bard-stage.js` 把它发给 Worker 的 `stage_unlock`；Worker 核对密钥 `PASSWORD_STAGE` 后从本站取 `songs-all.json` 发回全部曲目，再发一张凭证（30 天有效，每次用都续期；换了密码旧凭证失效）存在访客本机 `hj_stage_unlock`，之后打开舞台自动换成全部曲目（最多等 4 秒，超时先用公开曲目）。密码不对时什么也不提示，照常搜索。没设 `PASSWORD_STAGE` 时这个功能关闭。注意：隐藏的只是网站上的列表，仓库里的 MIDI 和谱面文件照样公开。
- 改曲子：平常用仓库根目录「花街加歌管理工具.zip」里的工具（Windows 双击运行：加歌、设显示 / 隐藏、改曲目信息〔曲名、副标题、作曲 / 演唱、分类、介绍、音色、疏密〕、删歌，生成上传用的压缩包）。手动改（`tools/stage-build/`，要 Python 3 与 `pip install mido numpy`）：
  - MIDI 放 `midi/<id>.mid`，在 `songs.py` 的 `SONGS` 加一行（曲名、副标题、歌手、分类，要公开就加 `show=True`；星级、时长、速度都自动算），`DEFAULT` 是第一次打开时选中的曲子（它是隐藏曲时，公开曲库改选公开曲里魔界花档星级最低、最短的一首）。
  - `python build.py` 重写 `songs.json`、`songs-all.json` 和 `charts/`（几秒，多余的谱面自动删掉；至少要有一首公开曲）；`python check.py` 体检，最后一行「问题 0」即可。删掉的曲子留下的 `midi/<id>.mid` 自己删。
  - 谱面规则在 `chart.py`，三档都以主旋律为主：
    - 找主旋律：多声部（多条轨道 / 通道）的先挑主旋律声部（最常是最高音、覆盖全曲、少和弦、轨道名带 melody / vocal / 旋律 等），其余声部算伴奏；主旋律声部里（单轨的曲子就是全部音），琶音式和弦算一簇取最高音，用动态规划沿时间挑出一条旋律线：靠近当时的上方音区、和前一个旋律音不大跳、不跳过更高的音、不在别的长音底下（参数在 `MEL`）。其余的簇算伴奏。
    - 挑音：旋律音按长度、和弦重音、拍点（MIDI 对齐网格时）、转折打分，再按最小间隔挑：仙人刺 0.5 秒、魔界花 0.25 秒、泰坦 0.125 秒，三档逐级包含。
    - 伴奏在旋律挑完之后才往主旋律的空档里塞，不会挤掉旋律音（`FILL`）：仙人刺不塞；魔界花在两个旋律起音之间空出 0.8 秒以上的地方稀疏地塞（离前后旋律音 0.3 秒、和别的要弹的音隔 0.75 秒）；泰坦在空出 0.3 秒以上的地方按泰坦的间隔塞（离旋律音 0.13 秒、间隔 0.125 秒）。参数按「三档总音数和只按间隔挑音时相当」定的（全曲库各档相差 1% 以内）。
    - 某首嫌密或嫌稀，在 `songs.py` 给它加 `gap`（>1 更稀，以上间隔都按它缩放）。
  - 星级按档各算一个（`songs.json` 的 `diffs` = [仙人刺, 魔界花, 泰坦]，`diff` 仍是魔界花档，给旧网页用）：每档按这一档的音符密度（平均每秒音数与最密 5 秒）在整个曲库里排名，最疏的 30% / 中间 45% / 最密的 25% 分三段，仙人刺 1~3 星、魔界花 2~4 星、泰坦 3~5 星；同一首越难的档不低于前一档。加减曲子后会重排。大厅、选曲窗口显示和筛选的都是当前所选难度的星级。
- 冒烟测试：`npm i --no-save jsdom && node tools/stage-build/smoke.mjs`（用 jsdom 跑 `bard-stage.js` 本体，期望「全部通过」；大部分场景用 `songs-all.json`，隐藏曲目与曲库密码单独一个场景）。
- 气泡重叠统计：`node tools/stage-build/overlap.mjs [曲目 id]`，对每首每档、电脑和手机两种屏幕各排一遍，报重叠对数、挨得近却同色的对数、跳距与同屏最远距离。改了 `placeNotes` 或谱面规则后跑一下。
- 只用到本机：`hj_stage_*`（曲目、难度、模式、音色、示范、判定模式、延迟、分类与星级筛选、显示方式、飞花线、点击范围、本机纪录 `hj_stage_best3` 与旧纪录 `hj_stage_best2`（见「得分与评级」）、曲库凭证 `hj_stage_unlock`；自动演奏不写纪录）。

## 小游戏助手

- 给 rp 店主持用，只在本机运行，不调用 Worker。弹窗外壳在 `index.html`（`#gamesOverlay`），内容与玩法在 `games.js`。
- 每个游戏带一段规则宏（`MACROS`），可展开编辑、一键复制；改过的存本机 `hj_games_macro_<id>`，「恢复默认」删掉即回到默认内容。超过 15 行会提示（游戏里一个宏最多 15 行）。播报类复制沿用该宏第一行的频道（`/p`、`/y`）。
- 数字炸弹：炸弹在范围里（含两端），随机或指定；猜的数成为新的边界（不加减 1，重复猜边界范围不变），范围越小字越大、引线越短。只剩 5 个数（`BOMB_TENSE`）时进入紧张时刻：字号撑满、红光按心跳节奏闪，之后猜不中提示和播报都是「xxx不是炸弹！」、记录划掉，大字范围照样缩小，猜中播放爆炸动画（不显示任何提示文字）。可撤销一步、偷看炸弹、复制当前范围的播报。可填玩家人数（存本机 `hj_games_bomb_players`），「当前玩家」从 1 号开始，每猜一次轮到下一位、最后一位之后回到 1 号，‹ › 可手动调整，撤销时一并退回。
- 飞花令：「任意字序」对应简单版规则，「严格字序」对应困难版（第 N 位发言人的令字在第 N 个字，7 位一轮，核对通过自动轮到下一位）。令字盘是简单版规则里的四十个字，也可以自定。
  - 自带题库在 `POEM_SRC`（`作者|篇名|句 句 句`，只收单句、不含标点，约 1230 句常见名篇），扩充题库在 `games-poems.js`（同样格式，约 7.5 万句，整理自 chinese-poetry 开源语料库：唐诗三百首、宋词三百首等选本加上唐宋名家诗词按作者分档摘取，并保证严格字序下 40 个令字的每个字位都至少有 12 句可出题，打开小游戏助手时后台加载）。同一句以先出现的出处为准。「提示」「答案」只用 4~9 字的句子，优先自带的名篇，其次五言、七言。改动后检查：严格字序下哪些令字缺位置，网页上会把它们显示为虚线框，「随机令字」不会抽到。
  - 「提示」从一句答案里取字、补足 10 个打乱（同人机验证的文科生）；「答案」给整句和出处，「换一句」优先给本局没出现过的。
  - 「核对」：令字（严格字序还看位置）→ 本局是否说过 → 题库出处；题库外的句子以橙字提示「请主持人确认是否是诗句」，主持人点「确认过关」才算过关（「不算」则不计）。繁体会先转成简体（`TRAD_PAIRS`）。
- 谁是卧底：词库在 `SPY_SRC`（`大类|小类|词 词 词`），每次从同一小类里抽两个词，平民 / 卧底各一（网页上不显示是哪一类）；可按大类筛选、交换、遮住，最近 40 组不重复。新增大类要同时在 `SPY_KINDS` 登记名称。
- 只存本机：当前页签 `hj_games_tab`、飞花令玩法 `hj_games_poem_mode`、词语类型 `hj_games_spy_kind`；对局进度只在打开的页面里，刷新即重来。
- 「更多」里的入口图标是羽毛笔（`assets/site/games-glyph.png`，白色形状作遮罩，颜色跟随其他按钮）。

## 闹铃

- 只存本机（`hj_alarm_items`），页面开着才会响。页面在后台（切到别的标签页、最小化）时响铃会另弹系统通知（`alarmNotify`）：权限只在添加闹铃 / 倒计时时问一次（`hj_alarm_notify`），有离线缓存时经 `sw.js` 弹（手机浏览器只认这种），点通知由 `sw.js` 的 `notificationclick` 回到开着的页面。
- 页面关掉后网页没法再响：浏览器不给网页定时唤醒（没有推送服务器做不到），所以有还没响的闹铃 / 正在走的倒计时时，离开网站会弹浏览器的「确定离开？」（`alarmLeaveGuard`；只在有这样的闹铃时才挂 `beforeunload`，点本站链接跳转不问）。

## 下拉框与日期选择

- 鼠标操作时用站内弹层（`main.js`「下拉与日期选择」），触屏保留系统选择器，日期类只在 Chromium 上替换。
- 键盘：会叫出浏览器自带面板的按键都改成打开站内弹层（`pickNativeKey`）—— 下拉框：空格、回车、F4、Alt+↑↓，苹果电脑上光按 ↑↓；日期 / 时间：空格、F4、Alt+↑↓。弹层开着时这些键不再传给浏览器。

## 滚动条

- 卡片、弹窗里的滚动条统一成细玻璃条（`style.css` 开头的 `--sb-*`）：夜间紫藤色、白天琥珀色，舞台固定夜间配色；页面本身的滚动条不改。Chrome / Edge / Safari 用 `::-webkit-scrollbar`，Firefox 用 `scrollbar-color`。要藏起滚动条的地方照旧写 `scrollbar-width: none` 和 `::-webkit-scrollbar { display: none }`。

## 搜索引擎与分享卡片

- 根目录 `robots.txt`、`sitemap.xml`（首页、/activity/、/previous/；不经 build，直接放根目录，加独立页面时手动补）。
- `build.mjs` 生成三个页面时按 `config.js` 写 `<head>`：/activity/ 的分享标题、描述换成最新活动的；/previous/ 换成往期活动列表；JSON-LD 结构化数据 —— 首页 `WebSite`、/activity/ 最新活动的 `Event`、/previous/ 往期活动的 `Event` 列表（`ItemList`）。活动日期从 `dateLabel` 认（「2026年1月1日–1月2日」「2025年9月21日 20:30–0:00」这类，北京时间），只写了年份或季节的不生成 `Event`；最新活动的 `dateLabel` 还空着，填上后才有它的 `Event`。分享图只用 jpg / png（QQ、微信不一定认 webp），否则用 `og-image.jpg`。
- `#event-<id>` 这种 hash 地址爬虫和 QQ / B 站抓不到单独的卡片；要每个往期活动都有自己的卡片，得给每个活动生成独立页面（如 /previous/<id>/），每次发布都要多传这些页面，暂未做。

## 缩略图

- `resized/720`、`resized/1280` 由 `tools/make-thumbs.py` 按 `config.js` 的写法生成：`cover` 两档都要（往期卡片 720、详情页头图 1280），`image:`（小型回顾、标签页外链磁贴）与 `infogal/` 720，其余图片（标签页图集、海报、视频封面）1280。改 `main.js` 里 `resizedSrc` / `data-bg-w` 用的档位时，脚本里的规则要一起改。

## 购票页余票

- 余票显示方式在管理页「购票管理 → 购票页显示」（具体张数 / 大致范围 / 不显示）。购票关闭时购票页一律不显示余票（`ticket.js` 的 `paintTicketStock`），只留刷新票额、预计开启时间的小字；提交时才发现已关闭也会立即收起。管理页预览会写明「购票关闭中，访客看不到余票」。

## 购票只读端

- 「购票情况」查看页（查看密码登录）可在管理页「购票管理 → 只读端」手动开关，也可设定时开放 / 关闭（`ticket_viewer_open_at` / `_close_at`，同购票的定时开关：到点后第一个请求执行并清除；手动开放清掉定时开放，手动关闭清掉定时关闭）。关着时登录提示带上定时开放时间。
- 查看密码只在 Cloudflare 改（Worker 密钥 `PASSWORD_VIEW`）。

## 全站开关

- 管理页「分享功能开关」里的「全站开关」。关闭后除 `#internal` 外只显示背景与「网站正在维护中……」。
- Worker 接口：`get_maintenance`、`set_maintenance`，`get_site_state` 带 `maintenance`。前端在本机记一份（`hj_maint`），下次进站由 `boot.js` 立即套用。
- 只是前端遮挡，接口本身不受影响。

## 管理页新提交提示

- 「反馈建议箱」「场地预约」「活动问卷」按钮右上角的小红点：有本机还没看过的新提交。
- 每个面板在本机记一份看过的最大编号（`hj_admin_seen`，问卷按问卷 id 分开记）。登录管理页时、之后每 5 分钟（页面在前台且停在内部入口时）后台读一次三个列表，编号比记下的大就亮点；打开面板读到数据即算看过，点随之消失。
- 场地预约只算访客在网站上登记的（`source` 为 `web`），后台录入、金数据导入的不算。
- 只用现有的 `feedback_admin_list`、`venue_admin_list`、`survey_admin_list`，Worker 不用改。换浏览器或清了缓存，第一次登录时有提交的面板都会亮一次。
- 反馈建议箱按钮里原有的数字是「未处理」条数，和小红点是两回事，登录后也会随后台读取一起更新。

## 发布

1. 修改 `_src/` 中的文件。
2. 将 `index.html` 中所有 `?v=` 后的版本号统一换成新值（如 `20261015a`）。
3. 生成发布版（Node.js 18+，`.nvmrc` 写的是验证过的 24）：`cd _src && npm ci && npm run build`，同时生成 `activity/`、`previous/` 两个独立入口。esbuild 锁定为 0.28.2（`package.json` + `package-lock.json`），换机器、换时间重新生成，压缩结果逐字节一致；升级 esbuild 时改 `package.json` 后运行 `npm install` 更新锁文件，并对比一次生成结果。
4. 上传 `_src/` 与根目录中有变化的文件。

新增图片后运行 `python tools/make-thumbs.py`；标题字体已含约 2900 个常用字，标题用到生僻字时再运行 `python tools/make-brush-font.py`（会重写 `style.css` 开头的 @font-face）。

停用离线缓存：按 `sw.js` 开头的说明替换根目录的 `sw.js`。

注意：同一个版本号下改了文件、重新上传，访客的离线缓存仍按版本号认，会一直用旧文件；每次上传都要换新的 `?v=`。

一次性重置：`main.js` 的 `RESET_ID` 换一个新值，每位访客下次进站执行一次 `runOneTimeReset`（记在本机 `hj_reset_done`）。现在的内容（`20261009j`，评级分档与判定分折算改版）：舞台演奏与吟游诗人模拟器的本机纪录清空、设置恢复默认（删 `hj_stage_*`、`hj_bard_*`，只保留曲库凭证 `hj_stage_unlock`），并删掉当前版本以外的离线缓存（`hj-` 开头的 Cache Storage，含图片缓存）。
